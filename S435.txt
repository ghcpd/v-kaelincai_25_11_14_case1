This experiment evaluates AI models’ ability to design, implement and verify a set of playback UX and performance enhancements for a video course player. Project A reproduces the baseline behavior (current player). Project B implements the enhancements: progress memory & auto-resume, adjustable playback speed (0.75×–2×), auto-skip learned segments, lazy/adaptive resolution loading and improved buffering, and time-synced notes with quick-jump on hover. Validation includes functional correctness, performance under variable network conditions, and user-visible evidence (screenshots and logs).
Key evaluation criteria
• Functional correctness of all enhancement features (resume, speed control, skip, adaptive buffering, notes sync).
• Performance improvement: reduced time-to-first-frame, smoother resolution switches, fewer stalls under constrained bandwidth.
• Robustness: correct behavior under network jitter, offline/resume scenarios, and malformed note timestamps.
• Test coverage: unit tests for logic and E2E tests covering interactive flows and performance metrics.
• Reproducibility: environment scripts and one-command runs that produce machine-readable results and comparative reports.

## Limitations & Pitfalls
- This is a demo / simulation (not real MP4/fragment streaming): the player uses sequential SVG frames in the canvas to simulate playback. Real media files and CDN-bitrate adaptation can behave differently.
- Network shaping is simulated via `bandwidth_kbps` and `latency_ms` query parameters; this is an approximation.
- Extreme playback rates (2×) might produce different audio/video AV-sync behavior in real browsers and hardware; our simulated player increments times logically without audio tracks.
- For production-grade real media tests, use real MP4/Fragmented playback and a harness that can shape traffic at the OS or container network layer and measure with MMV/TC or web-platform-benchmarking.
